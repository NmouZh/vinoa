## 1. 最小完备集合

REC 方向实际用到的语义位只有 **8 个**。token 表因此以 8 位为核心，另加 5 个派生/遗留键（保持 `render.py` 既有 key 兼容）。

| 类 | token 名 | 说明 |
|---|---|---|
| 语义四色 | `ok` `err` `warn` `accent` | 成功 / 失败 / 警告 / 强调 |
| 文字阶梯 | `fg` `dim` `faint` | 主要 / 次要 / 极次要 |
| 结构 | `border` | 整屏框 + 预览分栏竖线 |
| 派生 | `accentb` `title` `sel` | 字重变体（见 §3.7） |
| 信息徽标 | `hdr` | REC 框右上角**页名徽标**（`rec1`–`rec4` 各一处）；见 §3.7 |
| 遗留 | `hdrb` | **仅 P4 原型使用**（bg + bold）；P4 的「右上就绪状态块」已被 #19 否决（见 §3.7） |

**8 位是完备的**，因为 REC 只有一种强调（`accent`）——direction.md §2.3 的「颜色只承载语义、不做装饰」把色位数量压到了这个下界。任何新增色位都意味着新增语义，必须回到 #19 重新裁定。

## 2. 三档色深与降级层级

| 档 | 触发 | 放弃什么 |
|---|---|---|
| **真彩 24-bit** | `COLORTERM=truecolor` 等（探测规则属 #25） | 什么都不放弃 |
| **256 色** | 默认现代终端 | 放弃精确色相，保留全部 8 位的**可辨性** |
| **16 色** | `TERM` 只声明 16 色 | 放弃无彩阶梯的第 4 级（`faint` 与 `border` 合并）；放弃底色块 |
| **无色** | `NO_COLOR` / `TERM=dumb` / stdout 非 TTY（触发与优先级属 #25） | 放弃**全部**颜色；语义改由**字形 + 缩进 + 列位**承担 |

降级是**单向**的：任何档位下的输出都必须能被上一档正确渲染，且**语义不得丢失**。§3.5 逐个语义位给出无色替代，§4 给出字形的 ASCII 回退。

### 3.2 真彩档取值从哪来 —— 派生规则，不是发明

**规则：真彩档 = 256 档基准值所指向的、未经量化的人眼目标色。**

推导过程（可复现）：

1. 256 档的 8 个基准值全部是 xterm 6×6×6 立方体 / 24 级灰阶上的格点，它们的 hex 是 `#d0d0d0` `#8a8a8a` `#585858` `#5f5f87` `#5fafd7` `#87d787` `#d7af5f` `#ff8787`。立方体量化让每个值都偏离了原意（尤其 `dim`/`faint` 被压成**纯灰**，丢掉了冷色偏）。
2. 9 张原型已经建立在一个明确的调色板上：`ansishot.py` 的 `DEFAULT_BG = #1e1e2e` 与 `DEFAULT_FG = #cdd6f4` 就是 **Catppuccin Mocha** 的 `Base` / `Text`。也就是说原型**本来就画在 Mocha 上**，只是颜色经由 256 立方体绕了一圈。
3. 因此真彩档 = **把每个语义位映射到 Mocha 里对应的语义角色**（不是取最近色，而是取角色）。映射结果：

   | token | 256 基准 | Mocha 角色 | 色相差 |
   |---|---|---|---|
   | `fg` | 252 `#d0d0d0` | `Text #cdd6f4` | — |
   | `dim` | 245 `#8a8a8a` | `Subtext0 #a6adc8` | — |
   | `faint` | 240 `#585858` | `Overlay0 #6c7086` | — |
   | `border` | 60 `#5f5f87` | `Surface2 #585b70` | −7.5° |
   | `accent` | 74 `#5fafd7` | `Sapphire #74c7ec` | −1.5° |
   | `ok` | 114 `#87d787` | `Green #a6e3a1` | −4.5° |
   | `warn` | 179 `#d7af5f` | `Peach #fab387` | −17.0° |
   | `err` | 210 `#ff8787` | `Red #f38ba8` | 343.3° vs 0° |
   | `sel` | 111 `#87afff` | `Blue #89b4fa` | −2.8° |

   9 个基准值**各自命中一个不同的 Mocha 角色**，没有两个撞到同一个——这是「基准值本来就取自 Mocha」的证据。6/9 的色相差在 8° 以内；两个例外（`warn`→`Peach`、`err`→`Red`）恰好就是 Mocha 里承担警告/错误语义的角色，取角色优于取色相。
4. `err` 的色相从 0°（正红）移到 343.3°（Mocha Red 偏粉）是**有意的**：正红 `#ff8787` 在深底上偏「报警器」，而 direction.md §2.3 要求错误与警告在**同一份视觉语气**里可辨（错误不是灾难，是一次校验失败）。粉色红与 `warn` 的橙色（23°）色相差 40°，仍然可辨。

**被否掉的两种真彩取值方式**：

| 否掉 | 理由 |
|---|---|
| 真彩档直接沿用 256 的 hex | 真彩档就不存在了——终端仍收到 `38;5;n`，用户拿不到任何额外色深。三档表会退化成两档，`COLORTERM=truecolor` 的探测也就白做。 |
| 手工调一批「更好看的」真彩色 | 不可复核：9 张原型建立在一个既有调色板上，另起一套意味着原型与实现不再同源，人眼验收过的 PNG 就不再是实现的证据。 |

### 3.3 256 档为何冻结在现有 `S` 表

256 档**逐字节保持** `render.py` 第 26–42 行的既有取值。两个理由：

1. **原型是已验收的证据**：9 张 PNG 是人眼验收过的产物，256 档是它们的实际渲染档位。改动 256 值等于让验收过的图失效。
2. **256 是唯一能同时提供 4 级无彩阶梯的档位**：灰阶 252 / 245 / 240 三级 + 冷灰 60，正好铺满 `fg` / `dim` / `faint` / `border`。16 色做不到（见 §3.4）。

`render.py` 里的 `S` 表**从 `TIERS["256"]` 派生**，而不是独立硬编码——这样 token 表是唯一来源，且派生出的 SGR 与改前逐字节相同（回归可证，见 §7）。

### 3.4 16 档为何不取最近邻

**最近邻映射会摧毁语义。** 实测把 9 个真彩值各自映射到 xterm 16 色最近邻，结果：

| token | 最近邻 | 撞车 |
|---|---|---|
| `fg` | 7 `#e5e5e5` | ← |
| `dim` | 7 `#e5e5e5` | 与 `fg` 同格 |
| `ok` | 7 `#e5e5e5` | 与 `fg` 同格 |
| `warn` | 7 `#e5e5e5` | 与 `fg` 同格 |
| `err` | 7 `#e5e5e5` | 与 `fg` 同格 |
| `faint` | 8 `#7f7f7f` | ← |
| `border` | 8 `#7f7f7f` | 与 `faint` 同格 |
| `accent` | 12 `#5c5cff` | ← |
| `sel` | 12 `#5c5cff` | 与 `accent` 同格 |

9 个语义位塌缩成 **3 格**：`ok` / `warn` / `err` 与 `fg` 全部变成同一个亮白——**失败与成功在 16 色终端里将完全无法区分**。这直接违反 §2 的「语义不得丢失」。

**采用的规则：保角色，不保色相距离。**

1. **色相族优先**：先按语义选 ANSI 色相族（ok→绿、err→红、warn→黄、accent→青、sel→蓝），再在该族里选**对比度最高的那个**（`30–37` 普通 vs `90–97` 亮色）。
2. 于是 `err` 取 `91`（亮红，对比度 4.10）而非 `31`（普通红，2.81）——普通红在深底上太暗。
3. **无彩阶梯只剩 3 级**：16 色里可用的无彩色只有 `97`（亮白，16.40）/ `37`（白，13.02）/ `90`（亮黑，4.10）。`30`（黑）在深底上不可见，不可用。所以 `faint` 与 `border` **合并到 `90`**——第 4 级在 16 色档**不存在**。
4. 合并的后果必须写明：**16 色档下 `faint` 与 `border` 不可辨**。这不是缺陷而是边界，代价由 §6 的层级规则兜住——`faint` 与 `border` 本来就不靠颜色区分（一个是框，一个是分隔符/元信息，靠字形与列位）。

**16 档的两条硬性附加要求**（因为色轴变弱，必须补非色轴）：

- `err` 在 16 色档的对比度只有 4.10，与 `faint`/`border` 同级 ⇒ **`err` 必须同时带 `✗` 字形**，不得只靠颜色（真彩/256 档同样建议带，见 §4）。
- `dim`(`37`) 与 `fg`(`97`) 的对比度只差 1.26 倍，色轴很弱 ⇒ **`dim` 必须同时落在标签列（col 3）而 `fg` 落在取值列（col 16）**，不得把二者放在同一列靠颜色区分（§6 的层级规则已经强制了这一点）。

### 3.5 无色降级：每个语义位怎么保持可辨

无色档移除全部颜色后，**语义必须由非颜色手段承担**。这张表是硬契约，#25 直接引用：

| token | 无色替代 | 为什么仍然可辨 |
|---|---|---|
| `ok` | 行首 `✓` + 缩进 0 | 字形本身即语义；`✓` 与 `✗` 在纯文本里也是对立符号 |
| `err` | 行首 `✗` + 缩进 0 | 同上。**错误绝不允许只靠颜色**——这是本表最重要的一条 |
| `warn` | 行首 `!` + 缩进 0 | `!` 是 ASCII，连 ASCII 回退档都不用换 |
| `accent` | 当前项 `❯`（列位固定为标记列）/ 导航当前位置 `▸` | 标记列是**独占列**：整屏只有当前项在该列有字形 |
| `fg` | **完全不发色码**（不是"发默认前景色"） | 让终端用自己的默认前景；`NO_COLOR` 下不得出现 `38;5;252`（§3.5） |
| `dim` | **缩进 +1 级（2 格）**；行内则前置 `·` | 缩进是不可被颜色移除的轴 |
| `faint` | **缩进 +1 级 + `·` 前缀**；元信息右对齐到 `col.content.right` | 缩进 + 列位双重承担 |
| `border` | 保留框线字形（`╭╮╰╯─│`） | 边框从来不是靠颜色成立的 |

**无色档下 `dim` 与 `faint` 合并为同一档**（都变成默认前景）。这是**唯一允许的合并**，因为它们的区分在无色档**已由缩进接管**：`dim` 是 +1 级，`faint` 是 +1 级加 `·` 前缀。两者的信息因此没有丢失，只是换了一个轴。

**无色档不发出任何颜色 SGR**。注意这与「发出默认前景的 `fg` 色码」不是一回事：`fg` 在无色档**不是**「降级为默认前景色」，而是**完全不发色码**，让终端用它自己的默认前景。理由是这两者视觉等价但可测性不等价——前者会让 `NO_COLOR` 的输出里出现 `38;5;252`，而 #25 的硬契约是「CI（非 TTY）不得出现 ANSI 转义」。降级实现必须**不发**，而不是「发一个看起来一样的」。

> **一个必须写明的例外**：`render.py` 的 `Canvas.to_ansi()` 给**每一行**结尾追加 `\x1b[0m`（行尾重置）。这是渲染器的结构性行为，9 张既有原型全部依赖它，**不可移除**（移除会改动那 9 个已验收的 `.ans`）。因此「无色区域无转义」的精确含义是：**该区域内除行尾那一个 `\x1b[0m` 外，不含任何 SGR 转义**；行尾重置不属于该区域，也不承载颜色。§7 的断言按此措辞。

**禁止**：无色档不得把次要信息删掉（"反正看不见就不画了"）。降级只允许换轴，不允许减信息。

### 3.6 对比度序（硬约束）

三档必须各自满足同一套**相对序**。这是可断言的：

| 序 | 约束 | 真彩 | 256 | 16 |
|---|---|---|---|---|
| 1 | `fg` > `dim` > `faint` | 11.34 > 7.37 > 3.36 ✓ | 10.63 > 4.75 > 2.31 ✓ | 16.40 > 13.02 > 4.10 ✓ |
| 2 | `border` ≤ `faint` | 2.46 ≤ 3.36 ✓ | 2.71 > 2.31 ✗ | 4.10 = 4.10 ✓（合并） |
| 3 | 语义色 ≥ 3.0（可读下界） | 全 ≥ 7.08 ✓ | 全 ≥ 6.72 ✓ | `err` 4.10 / `sel` 3.46 ✓ |

序 2 在 256 档**不成立**，这是历史遗留而非有意设计：256 的 `border`(`60` `#5f5f87`) 因为带 240° 色相而在深底上比纯灰的 `faint`(`240` `#585858`) 略亮。**真彩档按正确序定义**（`border` ≤ `faint`），并把「边框不得比元信息更显眼」作为目标序——这是 direction.md §1「P3 减法」的直接推论。256 档的偏差保留不改（§3.3 理由），代价是框线在 256 档下比元信息略亮一点点，人眼几乎不可察。

序 3 的下界 **3.0** 取自 WCAG 对**非文本/大字号**元素的最低要求量级；正文文字的实际门槛更高（`dim` ≥ 4.5 已在三档成立，`faint` 是纯元信息故只要求 ≥ 2.0）。

### 3.7 派生键与遗留键

| key | 定义 | 状态 |
|---|---|---|
| `accentb` | `accent` + bold | 在用（导航当前位置、预览文件计数） |
| `title` | `fg` + bold | 在用（框标题） |
| `sel` | `sel` + bold | **deprecated**。它与 `accent` 语义重叠（都是"选中"），而 direction.md 只允许一个强调位。9 张原型**零处使用**。保留定义仅为 key 兼容；新代码不得使用，**不得**为它引入新的 UI 用法。 |
| `hdr` | 底色块（bg `border` + fg） | **在用**——用于 REC 的「框右上角页名徽标」（`rec1`–`rec4` 各一处，告诉你当前在第几页，是**信息**）。原型实测：`rec1`–`rec4` 各 1 处，`p1`/`p2`/`p3`/`shell` 为 0 处。**禁止**用它做状态块或装饰。 |
| `hdrb` | 底色块（bg `border` + fg + bold） | **仅 P4 原型使用**。P4 的「右上就绪状态块」（`就绪`）已被 #19 否决——它是**装饰而非语义**。保留定义仅为让 `p4.png` 仍能复现；**REC 不得使用 `hdrb`**。16 色档无底色块，改用**反显 SGR 7**。 |

**`hdr` 的裁定依据（两种用法必须分开）**：#19 否决的是 P4 的「右上**就绪状态块**」——它不承载信息；而 REC 的「框右上角**页名徽标**」承载「我在第几页」，与顶部导航条的页位互补（导航条给页序，徽标给当前页名），属于合法用法。**被否的是那个具体用法，不是这个 token。**

> **断言**：`docs/wayfinder/prototypes/{rec1,rec2,rec3,rec4}.ans` 第 0 行各含 1 处 `48;5;60;38;5;252`（页名徽标）；`p1`/`p2`/`p3`/`shell` 为 0 处。
>
> 实测（本裁定所依据的事实）：`p1 0 / p2 0 / p3 0 / p4 2(hdr)+1(hdrb) / rec1 1 / rec2 1 / rec3 1 / rec4 1 / shell 0`。`rec3.ans` 第 0 行尾部为 ` 目标服务端 ──╮`，即徽标内容。

## 4. 字形

每个字形都必须有 ASCII 回退形态。**ASCII 回退档与无色档是两个独立的轴**：无色档保留 Unicode 字形只去颜色（§3.5），ASCII 回退档替换字形（颜色可保留）。两者可同时命中（`TERM=dumb` + 非 UTF-8 locale）。

| 用途 | token | Unicode | ASCII 回退 | 宽度 | 说明 |
|---|---|---|---|---|---|
| 当前项光标 | `cursor` | `❯` | `>` | 1 | 独占标记列（`col.cursor`） |
| 导航当前位置 | `nav.current` | `▸` | `>` | 1 | + `accentb`；三态之一 |
| 导航已完成 | `nav.done` | `✓` | `+` | 1 | + `ok`；三态之一 |
| 导航未来页 | `nav.future` | `·` | `-` | 1 | + `faint`；三态之一 |
| 导航分隔 | `nav.sep` | `›` | `>` | 1 | + `faint` |
| 勾选框·选中 | `check.on` | `[x]` | `[x]` | 3 | **已是 ASCII，无需回退** |

**圆角 vs 直角的选取规则**：

- **默认圆角** `╭╮╰╯`（P1 骨架的识别特征，direction.md §1 采纳）。
- 直角 `┌┐└┘` 用于**降级但仍是 UTF-8** 的场景：`TERM` 声明不支持 DEC 制图但 locale 是 UTF-8（少见），或未来某平台字体缺圆角字形。它是「Unicode 可用、制图扩展不可用」这一格的填充。
- ASCII `+ - |` 是最终回退，用于 `TERM=dumb` 或非 UTF-8 locale。
- **三档的框线字符宽度全部为 1**（已实测 `unicodedata.east_asian_width` 均为 `N`/`A`，非 `W`/`F`）——所以框线不会因降级而错位。这是可以放心降级的依据。

**多帧字形（`spin.frames.*`）**：表中只有这两个 token 是**帧序列**而非单字形——其余 token 一个名字对应一个字形，这两个对应一组。规则：

- **帧是等宽的**：`spin.frames.unicode` 的 10 帧与 `spin.frames.ascii` 的 4 帧**逐帧宽度均为 1**（已实测：盲文 10 帧全部 `EAW = N`；ASCII 4 帧全部 `EAW = Na`）。因此帧循环**不会造成列位抖动**——这是 spinner 能在固定列位上原地重绘的前提。
- **帧序与帧率属 #23**：帧间隔 `motion.tick.spinner`（125 ms，8 Hz）与「何时推进/何时停」由 [motion.md](motion.md) §2 定义，本文只定义字形与宽度。
- **回退是整组的，不是逐帧的**：ASCII 档下 `spin.frames.unicode` **整组替换**为 `spin.frames.ascii`，不存在混用（ASCII 档下不得出现盲文字形）。回退后帧数从 10 降到 4，一圈时长相应变化——这不影响列位。
- **无色档不影响帧**：与 §3.5 一致，无色只去 SGR，帧照常循环（motion.md 的 H3「无色 ≠ 不动」）。spinner 在无色档仍是盲文帧。

**宽度已实测**：`❯ ▸ · ✓ ✗ ├ └ ─ │ ╭ ╮ ╰ ╯ ┌ ┐ └ ┘ █ ░ ▏ → ↑ ↓` 以及 `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` 全部宽度 1；`\|/-\` 亦为 1。中文页名（`工程` `构建` 等）宽度 2，与 `render.py` 的 `dwidth()` 一致。

## 6. 层级

标题 / 正文 / 次要靠 **色值 + 字重 + 缩进（含列位）** 三轴区分。**硬约束：任何相邻两级之间，至少有一个「非色值」的轴把它们分开。** 这条约束等价于「去掉颜色后层级依然成立」，是 §3.5 无色降级能work的前提。

| 级 | 定义 | 色值 | 字重 | 缩进/列位 |
|---|---|---|---|---|
| **L1 标题** | 框标题、导航条页位 | `title` = fg+bold | **bold** | 框线上 / `row.nav`，独占 |
| **L2 正文** | 标签 + 取值行 | 取值 `fg` | regular | 取值落在 `col 16`（两列）或 col 5（内联） |
| **L3 次要** | 标签、行内注释、右对齐元信息 | `dim` | regular | 标签落在 `col 3`；右对齐落在 `col.form.right` / `col.preview.right` |
| **L4 极次要** | 分隔符 `·`、说明行、元信息 | `faint` | regular | 缩进 +1 级，或 `·` 前缀 |

相邻两级的**非色轴**：

| 对 | 非色轴 | 无色档下是否仍然成立 |
|---|---|---|
| L1 ↔ L2 | **字重**（bold vs regular）+ 位置（框线/导航条 vs 框内正文） | ✓ bold 是 SGR 1，与颜色无关 |
| L2 ↔ L3 | **列位**（取值 col 16 vs 标签 col 3） | ✓ 列位与颜色无关 |
| L3 ↔ L4 | **缩进 + `·` 前缀** | ✓ 见 §3.5 |

**颜色只承载语义、不做装饰**，具体落实为三条：

1. 每个色位都在 §3.1 有唯一语义定义，不存在「为了好看而着色」的用法。
2. 全屏只有**一个**强调位 `accent`，且它只用于「当前位置 / 当前选中」（direction.md §4 明写）。
3. 层级的主轴是**字重与列位**，颜色是**冗余的第二轴**——这正是为什么三档降级都不会破坏层级。

## 7. 复现与验收

```bash
python3 docs/wayfinder/prototypes/render.py tokens   # 三档色值 + 字形 + 无色对照
python3 docs/wayfinder/prototypes/render.py          # 全部 10 张（9 张既有 + tokens）
```

`render.py` 中的 `S` 表**从本表 §3.1 的 256 档派生**（`TIERS["256"]` → `style()` → `S`）。派生保证：

- 既有 13 个 key 名全部保留（`fg` `dim` `faint` `border` `accent` `accentb` `ok` `warn` `err` `sel` `title` `hdr` `hdrb`）；
- 派生出的 SGR 字符串与改前**逐字节相同**，因此 9 张既有原型的 `.ans` 不变——回归是**可证**的，不是"看起来没坏"。

可断言的验收条目：

- `断言：python3 docs/wayfinder/prototypes/render.py → exit 0 且打印 10 行`
- `断言：python3 docs/wayfinder/prototypes/render.py tokens → 生成 tokens.png 与 tokens.ans`
- `断言：md5sum docs/wayfinder/prototypes/{rec1,rec2,rec3,rec4,p1,p2,p3,p4,shell}.ans 与改前一致`
- `断言：解析 tokens.ans，取 B 段（行 17–23）中可见列 ≥ 52 的字符，其间**除行尾 `\x1b[0m` 外不含任何 SGR 转义** → 0 violations`
- `断言：tokens.ans 中同时存在 38;2; / 38;5; / 裸 16 色码三种写法 → 三档齐全`

最后两条是 #25 可以直接机械翻译成测试的形式。第四条的可执行版本（`NOCOLOR_COL = 52` 与 `render.py` 的常量同源）：

```python
import re, unicodedata
raw = open("docs/wayfinder/prototypes/tokens.ans", "rb").read().decode()
SGR, NOCOLOR_COL, violations = re.compile(r"\x1b\[([0-9;]*)m"), 52, []
for r, line in enumerate(raw.split("\r\n")):
    if not (17 <= r <= 23):
        continue
    col, i = 0, 0
    while i < len(line):
        m = SGR.match(line, i)
        if m:
            params = m.group(1) or "0"
            if params != "0" and col >= NOCOLOR_COL:   # bare reset is structural
                violations.append((r, col, params))
            i = m.end(); continue
        if line[i] == "\x1b":
            j = i + 2
            while j < len(line) and not line[j].isalpha():
                j += 1
            i = j + 1; continue
        col += 2 if unicodedata.east_asian_width(line[i]) in ("W", "F") else 1
        i += 1
assert not violations, violations
```
