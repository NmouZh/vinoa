### 2.4 字段：位置（只读推导值）

现状 `src/wizard/mod.rs:91` 只打一行 `位置: <name>`，既没有值、也没有"这是推导出来的"这一层信息。定为：

| 态 | 渲染 |
|---|---|
| 全部态（无输入态、无错误态） | 标签行 `row 10`：`col.content.left` = `位置`（`dim`）；值行 `row 11`：`col.content.left` + `label.inline.gap` = 推导出的路径（`faint`）；同行右对齐至 `col.form.right` = `由名称推导`（`faint`） |
| 值 | `--output` 有值 → 该值；否则 `./` + 名称（与 `src/init.rs:239` 的 `target_dir` 一致）。就地初始化时即当前目录名 |
| 无色档 | 右对齐注释前置 `·`：`· 由名称推导`（[tokens.md](tokens.md) §3.5 的 `faint` 规则：缩进 +1 级 + `·` 前缀；行内右对齐场景取 `·` 前缀） |

**为什么值与注释都用 `faint` 而不是 `fg`**：这一行是**推导值**，与上面两个用户输入的字段不是同一类。若用 `fg`，它看起来像一个可编辑字段；`faint` 加上「无标记列」这两个非色轴，共同表达"这是算出来的"（[tokens.md](tokens.md) §6 的 L4 级）。它**不是错误态、也不参与校验**——目录已存在且非空的处理走 §11.3 的错误路径（`src/wizard/mod.rs` 之外），本页不显示。

**本页禁止项**：① 页**不得**出现文件数、`即将生成 N 个文件`、或任何文件树计数。预览面板在 ① 页只列**已确定存在的根文件**：`my-plugin/` 一行 + `└─ （选择平台后显示）` 一行（[direction.md](direction.md) §2.2 与 [rec1.png](../wayfinder/prototypes/rec1.png) 已按此修正）。文件总数从 ③ 页（平台选完）起才出现。

### 2.5 四态对照表（① 页）

| 态 | `名称` 输入行（`row 5`） | `包名` 输入行（`row 8`） | 辅助/错误行 | 标记列（`col.cursor`） |
|---|---|---|---|---|
| 待进入 | 取值列 = 值（`fg`） | 同左 | 辅助行（`faint`） | 空 |
| 输入态 | 值 + `caret`（`accent`） | 同左 | 辅助行（`faint`） | `❯`（`accent`） |
| 已确认态 | 值（`fg`） | 同左 | 辅助行（`faint`） | 空 |
| 错误态 | 值（`fg`） | 值（`fg`） | **错误行**（`err`） | `✗`（`err`） |

**「待进入」与「已确认」视觉相同是刻意的**：字段块内只有 3 行，`✓` 会挤掉辅助行或让块高在 3/4 行之间跳动——**块高跳动是布局抖动**，[motion.md](motion.md) §3.1 已判定这类抖动是缺陷。两态的区别由**焦点在哪**承担：全屏同时只有一个 `❯` + 一个 `caret`，这就是"当前项"的完整表达（[tokens.md](tokens.md) §3.5：标记列是独占列）。用户回答过什么，由预览面板与 ③ 页摘要承担，不由字段块重复一遍。

## 3. 校验错误的呈现（① 页核心条款）

现状：`inquire` 把 `Validation::Invalid(msg)` 渲染成**输入行下方插入的一行 `# 包名不合法: ...`**（`src/wizard/mod.rs:66–69` / `84–87` 传入，`inquire` 默认 `#` 前缀 + LightRed）。问题有两个：错误文案自带字段名（`包名不合法:`）却在视觉上与字段脱节；错误行是**插入**的，会让块高从 3 行变成 4 行，把下面的字段整体推下去。

### 3.1 规则

| # | 规则 | 理由 |
|---|---|---|
| **E1 贴住字段** | 错误行**固定占用该字段块的第三行**（名称 → `row 6`，包名 → `row 9`），与辅助行**互斥替换**，不新增行 | 块高恒为 3 行 ⇒ 出错时下面的字段**一格都不移动**（消除布局抖动） |
| **E1b 错误行从标记列起** | 错误行的 `✗` 落在 **`col.cursor`**（与输入行的 `❯` 同列），文案从 `col.cursor` + `label.inline.gap` 起——**与辅助行不同列**（辅助行从取值列起） | 这是 [degradation.md](degradation.md) §2.4 **R1** 的硬要求：`err` 承载行必须**以 `✗ ` 开头**（`line.startswith` 判定）。若 `✗` 落在取值列，行首是空格，R1 直接失败 |
| **E2 输入行标记列换字形** | 该字段**输入行**的 `col.cursor` 由 `❯` 换成 `✗`（`err` 字形 + `err` 色） | 错误定位到**行**，不需要读文案。`✗` 与 `❯` 同列 ⇒ 无色档仍然可辨（[tokens.md](tokens.md) §3.5） |
| **E3 文案不重复字段名** | 错误行文案**去掉 `包名不合法:` / `工程名不合法:` 前缀**，直接说哪里错。行首已有 `✗`，且它就在字段块内 | 字段名由上一行的标签承担；重复一遍是噪声 |
| **E4 错误行以 `✗ ` 开头** | 错误行 = `✗ ` + 说明（`err` 色），`✗` 落在 `col.cursor`（见 E1b）。`✗` 是**冗余的第二轴**，无色档下由它单独承担语义 | [tokens.md](tokens.md) §3.4 硬性要求「错误绝不允许只靠颜色」；[degradation.md](degradation.md) §2.4 **R1** 把它写成可判定规则 |
| **E4b 与 R4 的关系** | 错误态下 `col.cursor` 上的字形由 `❯` 变成 `✗`。**R4 要求该列有且仅有一个非空格字形**，且值域为 `{❯, >}`——`✗` **不在值域内** | **这是本文与 #25 §2.4 R4 的一处真实张力，须由 #25 裁定**（见 §5 冲突项 C12）。本文的立场：R4 的**意图**是「标记列独占、不出现第二个当前项」，错误态下 `col.cursor` 仍只有一个字形，意图不破；但**字面断言会失败**。在 #25 裁定前，实现按本文（`✗`）走 |
| **E5 边框不变色** | **不**改变整屏边框颜色，**不**画字段专属边框，**不**加背景块 | 整屏只有一个边框（[direction.md](direction.md) §1 的 P3 减法）；为单个字段改边框色会让"哪里错了"变成全屏信号，且边框是 `border` 位、不承载语义（[tokens.md](tokens.md) §6.3） |
| **E6 只标出错字段** | 同一时刻至多一个字段处于错误态（`inquire` 逐 prompt 校验的语义：当前 prompt 未通过就不进入下一个） | 与 `src/wizard/mod.rs:57–93` 的串行 prompt 结构一致，不引入跨字段批量校验 |
| **E7 高度预算固定** | 每个字段块 3 行，① 页正文恒占 `row.body.top` 起连续 8 行（3 字段 × 3 行 − 1 行 位置块只有 2 行 = 8）；错误不改变这个预算 | 见 [direction.md](direction.md) §2.3 的密度上限表：① 页 = 3 个字段块 |

### 3.2 文案表（逐字，含中英）

**错误行布局**：错误行的 `✗` 落在 **`col.cursor`**（与输入行的 `❯` 同列），其右 `label.inline.gap` 格留空，文案从 `col.cursor` + `label.inline.gap` 起。于是错误行**以 `✗ ` 开头**，满足 [degradation.md](degradation.md) §2.4 **R1**（行首判定 + 该行 `✗` 出现 1 次）。

**这带来一处与辅助行的列位差异，必须写明**：辅助行从**取值列**起，错误行从 **`col.cursor`** 起——两者相差 `label.inline.gap` 格。这是**有意的**：错误行要满足 R1（行首即 `✗`），而辅助行是 `faint` 级、满足 R6 的 `· ` 前缀分支即可。因此错误态的第三行在视觉上比辅助态**左移 2 格**——这个位移本身是「出错了」的第三个信号（除字形与颜色之外），也是它在无色档下仍能与辅助行区分开的原因。

文案长度上限 = `col.form.right` − 文案起始列 + 1 = **59 列**。**超限截断**：在 `col.form.right` 前以 `…` 收尾。

## 4. ② 构建页 · 压缩取舍与字段规格

### 4.1 决定：**压缩为只读摘要，保持 4 页，不与 ① 合并**

[direction.md](direction.md) §2.3 已裁定方向（压缩为只读摘要、页数保持 4 页）。本节把它落成可实现的精确版式，并**记录为什么不是另外两条路**——否则下个会话会重开这个取舍。

**采纳：本页 = 「确认并继续」式只读摘要，4 行正文（3 取值 + JDK），无任何可交互控件。**

理由（可复述的代价，不是"好看"）：

1. **四个唯一选项没有"选择"这个动作**。`src/wizard/mod.rs:98–101` 现在打的四行是常量；用户在本页**没有任何按键能改变结果**。一个整页只放常量，是把"导航"伪装成"输入"。
2. **它是重复经历的场景**。② 页夹在 ①（要打字）与 ③（全 flow 最密，7 个平台）之间；用户第二次运行向导时，这一页的阅读成本是纯开销。压成 4 行后它的成本从"一页"降到"四行"。
3. **`JDK` 是推导值不是选项**，它天然属于摘要而不属于表单。把它和三个常量并排，正好说明本页的性质：**它是 ③ 页的前置说明**，不是一页问题。
4. **保留页位（不合并）**：导航条已冻结 4 个页位（`1/4`…`4/4`，`direction.md` §2.3），合并会连带改动已冻结的 spec §4 页序与回退语义（`Nav::Back` 从 ③ 回到②还是①）。**用"压缩内容"换"不改页序"**，代价最小。
5. **保留「继续」这个动作**：本页仍需要一次 `Enter` 才能前进（不自动跳过）。理由见 §4.5。

**否掉的另外两条路**：

| 否掉 | 理由（代价可复述） |
|---|---|
| **压成两三行 / 与 ① 合并** | 与 ① 合并会让 ① 页正文从 8 行涨到 12–14 行，突破 [direction.md](direction.md) §2.3 的 ① 页密度上限（3 个字段块），且 ① 页的"块间紧贴"错误规则（§3.1 E1）会被插入的摘要行打断；合并还要重排回退语义。**压缩的收益是 4 行，合并的代价是重开页序。** |
| **照四行"选项"铺开**（每行带 `[x]` / `❯` 等选项字形） | 选项字形会让用户以为可以按键切换——**这是虚假的可供性（false affordance）**。用户按 `Space` 没有反应，比"少了一页"更糟。 |

**与 [direction.md](direction.md) §2.3 的差异（必须记）**：§2.3 写"页脚 2–3 行极次要说明"，`rec2.png` 里有 **3 行**说明。本规格定为 **2 行**，删掉第 3 行 `Java 版本不在这里问——它由 ③ 选的 MC 版本推出。`——因为该信息已由 `JDK` 行右侧的 `· 由 MC 版本经矩阵推导` **逐字承担**（§4.2），同一屏说两遍违反 [direction.md](direction.md) §1 的 P3 减法。这是本文对原型的**唯一内容删减**。

### 6.3 截断 / 换行（引用 #25 §5.3 的三类处置）

#25 §5.3 把内容分成三类，①② 页的映射：

| 类别 | ①② 页的实例 | 处置 |
|---|---|---|
| **hard（不可截断，换行）** | `位置` 的路径（`./my-plugin`）、`包名`（`com.example.myplugin`） | **换行**，续行缩进 `indent.unit`，**绝不截断** |
| **soft（可截断）** | 辅助行（`须匹配 …`）、② 页说明行、右对齐推导说明（`由名称推导` / `由 MC 版本经矩阵推导`） | 截断到 `W − 起始列 − 1`，末字符替换为 `…`（ASCII 档为 `...`） |
| **omit（可省略）** | ① 页无；② 页无（本页无进度条与分隔线） | — |

**两条本页特有的补充**：

1. **错误行按 hard 处理**（#25 §5.3 的 hard 清单是「标识性内容」，错误文案不在其中）。理由：错误是必须传达的信息，而 #25 §5.3 硬规则 5 又要求「极窄档不改变语义标记」——错误行若被截断成 `✗ 段 Example 不合法 · …`，用户看到的是被删掉的原因。因此：**错误行换行**（续行缩进 `indent.unit`），这是本页对 #25 §5.3 的**收紧**（不是冲突：§5.3 只规定 soft 必须带 `…`，不禁止把某类内容按 hard 处置）。
2. **右对齐推导说明在放不下时整条省略，而不是截半句**。它是 `faint` 级的冗余第二轴（[tokens.md](tokens.md) §6 的 L4），省略不丢语义——`JDK` / `位置` 的块末位置、无标记列、与上方隔 2 行已承担"推导值"的表达。这与 #25 §5.3 的 soft 规则不冲突：§5.3 要求「截断必留标记」，而**整条省略属于 omit 类**（重复性内容）。

### 6.4 无色档（引用 #25 §2.4 的判别式 R1–R8）

| token | ①② 页用法 | 无色替代 | 对应 #25 规则 |
|---|---|---|---|
| `fg` | 取值（`Java` / `Gradle` / `21` / 输入值） | **完全不发色码**（不是"发默认前景"） | — （断言 B7：不含 `38;5;252`、不含 `39`） |
| `dim` | 标签、页脚正文 | 标签本就在 `col.content.left`、取值在取值列，**列位**承担 | **R5** |
| `faint` | 辅助行、右对齐推导说明、② 页说明行 | 缩进 +1 级 + `· ` 前缀（右对齐形态满足 R6 的右端对齐分支） | **R6** |
| `accent` | `❯` 焦点标记、`caret` | **保留字形** `❯` / `▏`；**R4**：整帧在 `col.cursor` 上有且仅有一个非空格字形 | **R4** |

**本页满足 R7 / R8 的方式**：无色档与真彩档的**行数相等**（①② 页的版式不随颜色变化），且 `✗`/`✓`/`!`/`❯` 计数逐项相等（无色只把 `dim` 加缩进、把 `faint` 加 `· ` 前缀，均为**等宽替换**，不成片删除）。可用 #25 的断言 **B8 / B9** 直接验收。

**无色档下的 bold 保留**（#25 §0.2 裁定 4）：框标题的 `title`（= `fg` + bold）在无色档下**仍发 `\x1b[1m`**——它不承载颜色。①② 页正文没有 bold，所以该差异只影响框标题行。

### 6.5 ASCII 字形回退档（与无色档正交，引用 #25 §3）

`TERM=dumb` 或非 UTF-8 locale ⇒ `GlyphSet::Ascii`。**窄终端不触发它**（#25 §3.3）。

①② 页用到的字形与回退：`❯`→`>`，`✗`→`x`，`▏`→`|`，`╭╮╰╯`→`+`，`─`→`-`，`│`→`|`，`›`→`>`，`·`→`-`，`└─`→`` `- ``。

**宽度不变式**（#25 §3.2）：所有 Unicode 字形与它的 ASCII 回退**显示宽度相同**，因此字形回退**不改变任何列位**——本文 §1–§4 的全部列号在 ASCII 档下**逐列不变**。**唯一例外**是页脚的 `← →`（3 列）→ `<- ->`（5 列），它只出现在页脚行尾，不影响正文对齐。

### 6.6 非 TTY / `--json`

**①② 页不存在降级形态**：向导只在 `stdin` + `stdout` 都是 TTY 且未给 `--yes`、未给 `--config` 时运行（`src/wizard/mod.rs:20–23` 的 `should_run` 与 `src/init.rs:20` 的 `interactive`）。其余路径**根本不进入这两页**，全部走 `spec_from_args` 的默认值。

> 注意 #25 §1.4 的精确措辞：**「非 TTY」这个信号以 stdout 为准**（颜色可能写 stdout 或 stderr），而**「向导能不能跑」要求 stdin **与** stdout 都是 TTY**。两者是不同的判定，不要合并。
