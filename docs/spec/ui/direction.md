# vinoa 界面视觉方向锁定（#19）

> **状态**：锁定。本文只定**方向**，不定数值——数值全部在 [tokens.md](tokens.md)。
> **读者**：下游票 #21（渲染选型）、#22（token）、#23（动效）、#25（降级）、#26/#27（逐页规格）。
> **依据**：`docs/wayfinder/prototypes/` 下 9 张原型（`p1`–`p4`、`rec1`–`rec4`、`shell`）。复现：`python3 docs/wayfinder/prototypes/render.py`（PNG 由 `scripts/termcap/ansishot.py` 栅格化）。

## 1. 决策

**采用 REC：P1 骨架 + P3 减法 + P4 预览面板。**

一句话：**整屏一个边框 + 顶部导航条 + 右侧常驻「即将生成」预览；框内不做装饰，层级靠色值与缩进；一个屏幕只在同一张网格上绘制一次。**

三者的分工要写清楚，否则下个会话会把它当成三个并列候选重新投票：

| 来源 | 采纳的部分 | 丢弃的部分 |
|---|---|---|
| **P1** 克制专业 | 整屏圆角边框；顶部导航条（页名 + `n/4`） | 框内每行右侧重复的 `✓ 已选`；无预览面板 |
| **P3** 安静日志 | 减法：框内不加分隔线/不加嵌套框；层级靠**色值 + 缩进**而非装饰；次要信息用 `·` 分隔 | 「完全无 chrome」——没有常驻的页位与回退提示 |
| **P4** 面板质感 | 右侧常驻预览面板（`即将生成` + 文件树 + 跳过项） | 状态条、右上「就绪」状态块、右下面包屑、框内再套框 |

## 2. 三个取舍的裁定

### 2.1 顶部导航条 vs 左侧步骤轨 → **保留顶部导航条，否掉左侧步骤轨**

issue 说得对：两者**信息不同**。导航条给**页名与页位**（`✓1 工程 › ▸3 目标服务端 … 3/4`）；步骤轨给**已答内容的摘要**（`① 工程 / my-plugin`、`② 构建 / Java · Gradle`）。

裁定理由不是「导航条更好看」，而是**那份摘要不该由一条永久占宽的竖栏来承担**：

1. **横向成本**：步骤轨固定吃掉 26 列（P2 实测），预览面板还要 34 列，剩下的表单区只剩 ~40 列。而表单区正是第 ③ 页平台列表（`[x] paper` + 右对齐 `Java 21`）最需要宽度的地方。
2. **摘要已有归属**：预览面板本来就要回答「我的选择意味着什么」。第 ④ 页的预览里直接列出 `已选 · 示例代码 · 权限声明 · 质量工程 · git init`（见 `rec4.png`），第 ③ 页的预览里 `platforms/paper 7 files / bukkit 6 files` 就是平台选择的摘要。**同一份信息不需要两个面板各说一遍。**
3. 因此：**导航条负责「我在哪、怎么回去」，预览面板负责「我选了什么、意味着什么」。** 两者信息不重叠。

### 2.2 右侧「即将生成」预览面板 → **保留**

保留的理由是它**在教**：勾 `paper` → 树里多出 `platforms/bukkit 6 files`，这个因果是用户在别处看不到的。它把「选项」翻译成「产物」。

**这条决策的直接后果必须写明**：预览面板是一个**持续重绘的区域**，而 `inquire` 是「一问一渲染」，做不出常驻区域。**保留预览 = 要求全屏接管。** 这把 #21 推向 `ratatui`（见 §4）。

两条硬规则（原型已按此修正，规格不得回退）：

- **不许诺未确定的东西**：第 ①② 页平台未选、文件集未定 → 预览**只列已确定存在的根文件**（`settings.gradle.kts` / `build.gradle.kts` / `gradle/libs.versions.toml`），**不显示文件总数**。文件总数从第 ③ 页（平台选完）起才出现。
- 预览里的「跳过 N 项」按**原因**分组，不逐条铺 `when:` 表达式（详见 #24）。

### 2.3 四页密度上限 → **第 ② 页压缩为只读摘要；页数保持 4 页**

第 ② 页 v1 每项只有唯一取值（语言 Java / 构建系统 Gradle / Gradle DSL Kotlin），照四行铺开是浪费——它是用户重复经历的场景。

裁定：**保持 4 页**（spec §4 的页序与导航条 4 个页位已冻结，合并会连带改动已冻结的 spec），但第 ② 页**不再表现为「一组可选项」**，而是：

- 3 行 `标签 + 取值`（语言 / 构建系统 / Gradle DSL），**取值用主要文字色**、标签用次要色；
- JDK 单独一行，右侧以极次要色标注 **`由 MC 版本经矩阵推导`**——它是**推导值不是选项**，视觉上必须与上面三行区分；
- 页脚 2–3 行极次要说明（「本页无可选项」+ 为什么 Gradle DSL 只有 Kotlin），用户可跳过不读；
- **不显示文件总数**（§2.2 规则）。

各页密度上限（正文行数上限，不含边框与提示条）：

| 页 | 上限 | 说明 |
|---|---|---|
| ① 工程 | 名称 / 包名 / 位置 = 3 个字段块 | 位置是只读推导值；**不得**出现文件数 |
| ② 构建 | 4 行（3 取值 + JDK） | 只读摘要，见上 |
| ③ 目标服务端 | MC 版本（1 选中 + 至多 2 条邻项）/ 平台（至多 7 项）/ 元数据（2 选 1）/ 预检（去重后至多 2 行） | 全 flow 最密的一页；7 项平台是硬上限 |
| ④ 附加 | 5 个多选 + 4 个三态确认 + 1 行语言 | 两类控件必须视觉可分（详见 #27） |

## 3. 被否掉的选项与理由

**这些理由必须与方向一起记**——否则下个会话会把它们重新提出来。

| 否掉 | 理由（不是「不好看」，是可复述的代价） |
|---|---|
| **P2 左侧步骤轨** | 永久占用 26 列；其独有信息（已答摘要）已由预览面板承担（§2.1）。左栏 + 右预览 + 中间表单 = 100 列里挤三栏，表单区被压到放不下平台行。 |
| **P3 作为整体框架** | 「完全无 chrome」在**四页向导**里不成立：没有常驻页位就没有「我在第几页 / 能不能回退」。P3 的价值在**减法**（框内不加装饰），已按 §1 采纳。 |
| **P4 原样** | 装饰过剩：右上「就绪」状态块、右下 `1.21.11 · paper+bukkit` 面包屑、框内再套框，都是**装饰而非语义**。用户已拍板「颜色只承载语义」。只保留其预览面板。 |
| **P1 原样** | 无预览面板（放弃「教」的能力）；且每行右侧重复 `✓ 已选` 是冗余噪声——已选状态由标记与色值表达即可。 |
| **打字机 / 逐字 reveal / 彩虹渐变 / ASCII logo 庆典 / 完成庆祝动画** | 用户已明确拒绝，勿重开（详见 #23）。 |

## 4. 对下游票的直接约束

### → #21 渲染方案选型（**输入：需要全屏接管**）

- §2.2 保留了常驻预览面板 ⇒ **需要整屏布局与持续重绘** ⇒ `inquire` 的「一问一渲染」模型不成立。
- 因此 #21 应当选择 **`ratatui` + `crossterm` 全屏接管**；`inquire` 只剩「留作非全屏路径的降级实现」这一个可能的角色，且该角色本身要论证是否值得维护两套。
- #21 的 ADR **必须**同时记下「谁负责无色降级」：降级由 **vinoa 自己**保证，不依赖 `ratatui` 提供（契约见 #25）。

### → #22 设计 token 表

token 必须至少覆盖 REC 实际用到的这些语义位（取自 `render.py` 的 `S` 表）：

- 边框（整屏框 + 预览分栏竖线）
- 顶部导航条的**三态标记**：已完成 `✓`(ok) / 当前 `▸`(accent+bold) / 未来 `·`(faint)
- 主要文字（取值）、次要文字（标签）、极次要（分隔符 `·`、元信息、说明行）
- 预览面板标题与文件计数（计数用 accent+bold，是唯一被强调的元信息）
- 语义四色：ok / warn / err / accent——**accent 只用于「当前位置」，不用于装饰**

### → #23 动效规格

- 采纳 P3 的减法意味着**框内不做动画**；动效只出现在 issue 已划定的三处。
- 预览面板的**重绘必须与主表单在同一张网格上**——它是 #23「消除重绘抖动」的第二个受害者（除 ③ 页叠印外）。

### → #25 界面降级契约（**宽度阈值来自本节**）

REC 的最小宽度是 **100 列**（表单区 3–63，分栏线 66，预览 67–99）。降级档位：

| 宽度 | 形态 |
|---|---|
| ≥ 100 | 完整 REC：边框 + 导航条 + 预览 |
| 80–99 | **丢弃预览面板**，表单占满；导航条保留 |
| < 80 | **丢弃整屏边框**，退化为 P3 式连续流；导航条压成一行页位 |
| 极窄（< 60） | 单栏 + 截断策略，详见 #25 |

## 5. 复现

```bash
python3 docs/wayfinder/prototypes/render.py          # 全部 9 张
python3 docs/wayfinder/prototypes/render.py rec1 rec3 shell
```

`docs/wayfinder/prototypes/*.ans` 是**源**（单元格网格 + SGR），`*.png` 是栅格化结果；改方向时改 `render.py` 并重跑，PNG 与 `.ans` 一起进版本库。
